# MemoryWiki v0.1.0 Release Notes Draft

First public release candidate for local-first, Markdown-native agent memory.

## Highlights

- Local Markdown/JSONL memory roots for project and optional global memory.
- Read-first recall through CLI and MCP.
- Explicit write gates for session saves, source ingest, crystallization,
  forget/delete, and global writes.
- Source provenance with SHA256 references.
- Conflict/update history for semantic memory.
- Hybrid recall with local lexical, embedding-style, and graph-style signals.
- Dry-run-first index maintenance and forget/delete workflows.
- Public synthetic example memory root, cross-project demo, mini benchmark,
  golden eval, public-clean gate, and release checker.

## Verification To Attach

- CI run: Linux, macOS, and Windows on Python 3.9 through 3.13.
- Public-clean scan: `python3 -m pytest tests/test_public_clean.py -q`.
- Test suite: `python3 -m pytest tests -q`.
- Golden eval: `memorywiki-golden-eval --project-root examples/memory-root --global-root examples/memory-root --case-file docs/memorywiki-golden-cases.json --format json`.
- Mini benchmark: `python3 benchmarks/mini_recall_benchmark.py --format markdown`.
- Release checker with generated manifest.
- MCP contract: `docs/memorywiki-mcp-v1-contract.json`.

## Known Limits

- Early Python-first CLI.
- Package-index install is prepared as a launch goal, but editable install is the
  current verified path until the package is published.
- Mini benchmark is a smoke test, not a broad retrieval benchmark.
- No hosted sync service.
- Memory content is treated as context data, not instructions.

## Release Checklist

- Confirm GitHub Actions is green on `main`.
- Generate release manifest in a temporary release directory.
- Build sdist and wheel, then run `twine check`.
- Attach release notes, benchmark output, release manifest, and MCP contract.
- Tag `v0.1.0` only after the final public-clean and release-check pass.
- Do not move a published tag; use a patch release if something is wrong.
