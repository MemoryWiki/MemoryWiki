# Roadmap

MemoryWiki is aiming for a focused v0.1 public launch first, then adoption and
retrieval-quality improvements from real feedback.

## 0 to 30 days: public launch foundation

- Make the README quickstart work in under two minutes.
- Publish `v0.1.0` with release notes, release manifest, MCP contract, and mini
  benchmark output.
- Keep Issues, Discussions, labels, and first-user templates ready before the
  repository is made public.
- Enable branch protection, secret scanning, push protection, and private
  vulnerability reporting as soon as repository visibility and account plan allow
  it.
- Fix install, MCP setup, and docs confusion before adding major new features.

## 30 to 60 days: developer adoption

- Add client-specific MCP setup guides for common coding-agent environments.
- Expand synthetic examples for coding repos, team handbooks, source ingest,
  review/promote workflows, and safe forget/delete flows.
- Add a reproducible retrieval-quality benchmark beyond the bundled mini smoke
  test.
- Publish fair comparison docs against hosted memory tools, vector DB notebooks,
  PKM-only workflows, and `AGENTS.md`-only memory.

## 60 to 90 days: community proof

- Turn repeated issue answers into docs and tutorials.
- Seed beginner-friendly issues for docs, examples, tests, and client configs.
- Publish short release notes every one to two weeks while feedback is active.
- Track stars, clones, issue response time, release downloads, package installs,
  and recurring docs confusion themes.

## Non-goals for v0.1.x

- Hosted sync service.
- Automatic background saving without explicit user approval.
- Claims based on large benchmarks before the benchmark is reproducible.
- Treating memory content as higher-priority instructions.
